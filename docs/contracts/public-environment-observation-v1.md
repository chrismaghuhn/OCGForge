# Perspective-safe public environment observation v1

## Contract IDs

```text
ocgforge.public_environment_observation.v1
ocgforge.public_safe_state.v1
```

`ocgforge.public_environment_observation.v1` is the policy-facing
observation consumed by `ocgforge.episodic_environment.v2`. It is not an
alias for `ygo.player_observation.v1`. The nested safe-state bytes have their
own fixed schema so that a caller cannot substitute an arbitrary string or
the v1 observation serialization.

## 1. Boundary and ownership

The observation layer may retain an attached `PlayerObservation v1` record for
internal diagnostics, protocol integration, and trace evidence. The public
environment performs this projection:

```text
PlayerObservation v1
    -> canonical_public_safe_state_bytes(PlayerObservation)
    -> safe public decision-context projection
    -> PublicEnvironmentObservation v1
    -> Agent / Teacher / Model
```

The public-state serializer owns the safe-state bytes and
`public_observation_digest`. Its API accepts a `PlayerObservation`, not
caller-supplied bytes:

```cpp
std::vector<std::uint8_t> canonical_public_safe_state_bytes(
    const PlayerObservation& observation);

PublicEnvironmentObservationInput project_public_observation(
    const PlayerObservation& observation);
```

The projector must call the serializer internally. A call site must not pass
canonical JSON, a precomputed digest, raw engine bytes, or any other
caller-chosen state string. In the C++ value returned by the projector, the
safe-state byte vector is read-only to callers; a caller-created input without
projected bytes is rejected by the outer codec.

## 2. Public shape

```text
PublicEnvironmentObservation {
    schema_version = ocgforge.public_environment_observation.v1
    perspective_player
    decision_index
    canonical_safe_state_bytes
    public_decision_context
    public_observation_digest
}

public_decision_context {
    kind                       optional public request-family token
    player                     optional acting player
    referenced_entities        sorted current safe observation locators
}
```

The `canonical_safe_state_bytes` value is generated by the
`ocgforge.public_safe_state.v1` serializer below. It contains the
perspective-safe state fields owned by `PlayerObservation v1`:
`globals`, `zones`, `entities`, `relationships`, `chain`,
`visible_events`, and `match_context`.

The public value does not contain:

- `decision_id`;
- `continuation_id`;
- `raw_message_hash`;
- internal candidate/domain digests;
- top-level `engine_step_index`;
- `PlayerObservation.observation_hash`;
- any field omitted by the safe-state encoding below.

The public projection fails closed if a state or context field cannot be
proven perspective-safe.

## 3. Canonical public observation bytes

All integers are unsigned big-endian unless stated otherwise. A string is
`u32be byte_length || UTF-8 bytes`. A byte vector is
`u32be byte_length || raw bytes`. An optional value is
`presence:u8` (`0` absent, `1` present), followed by its value when present.
Booleans use `u8 0` or `1`. Signed `i32` values use their two's-complement
`u32` bits.

The outer observation byte sequence is ordered as follows:

| Order | Field | Encoding |
| ---: | --- | --- |
| 0 | identity domain | string `ocgforge.public_environment_observation.v1` |
| 1 | identity schema | string `ocgforge.public_environment_observation.v1` |
| 2 | perspective player | `u8` |
| 3 | decision index | `u64be` |
| 4 | canonical safe-state bytes | length-prefixed raw bytes |
| 5 | context kind | optional canonical lower-case token string |
| 6 | context player | optional `u8` |
| 7 | referenced entities | `u32` count followed by sorted locator strings |

The `public_observation_digest` is the lowercase SHA-256 of these outer
bytes. The digest is the only observation identity admitted to the public
semantic decision identity.

### 3.1 Safe-state schema

The nested safe-state bytes are ordered as follows:

| Order | Field | Encoding |
| ---: | --- | --- |
| 0 | safe-state domain | string `ocgforge.public_safe_state.v1` |
| 1 | safe-state schema | string `ocgforge.public_safe_state.v1` |
| 2 | globals | fields in the order below |
| 3 | zones | count and canonical zone records |
| 4 | entities | count and canonical entity records |
| 5 | relationships | count and canonical relationship records |
| 6 | chain | length, link count, and link records |
| 7 | visible events | count and canonical event records |
| 8 | match context | fields in the order below |

`globals` fields are ordered:

```text
duel_flags:u64be
life_points: u32 count, followed by ordered u32be values
player_to_act: optional u8
turn_player: optional u8
turn_count: optional u32be
phase: optional u32be
chain_length:u32be
winner: optional u8
win_reason: optional u8
terminal:bool
```

Zones are copied and sorted by
`(player, kind, total_count, public_identity_count, hidden_count,
player_observable_order)`. Each record is:

```text
player:u8
kind:u8
total_count:u32be
public_identity_count:u32be
hidden_count:u32be
player_observable_order:bool
```

Entities are copied and sorted by `locator.value`; locator values must be
non-empty, printable, and unique. Each record is:

```text
locator:string
identity_known:bool
passcode:optional u32be
owner:optional u8
controller:optional u8
zone:u8
sequence:optional u32be
overlay_sequence:optional u32be
position:u8
face_up:bool
face_down:bool
printed:optional CardProperties
current:optional CardProperties
```

For a card with `identity_known=false`, `passcode`, `printed`, and `current`
must all be absent; otherwise projection fails closed. Thus a hidden card
cannot reach the safe-state bytes through an inconsistent `PlayerObservation`.
Known card properties retain the following exact field order:

```text
type:optional u32be
attribute:optional u32be
race:optional u64be
attack:optional signed i32
defense:optional signed i32
base_attack:optional signed i32
base_defense:optional signed i32
level:optional u32be
rank:optional u32be
link_rating:optional u32be
link_markers:u32 count, sorted by enum code, followed by u8 codes
left_scale:optional u32be
right_scale:optional u32be
status_flags:optional u32be
counters:u32 count, sorted by (type, count), followed by type:u32be,count:u32be pairs
```

Relationships are copied and sorted by
`(kind, source.value, target.value)`. Each record is:

```text
kind:u8
source:string
target:string
```

Chain fields are `length:u32be`, link count, then links in the authoritative
`chain.links` vector order. Each link is:

```text
index:u32be
activating_player:optional u8
source:optional locator string
activation_zone:optional u8
effect_description:optional u64be
targets:u32 count, followed by lexicographically sorted locator strings
```

Visible events are copied and sorted by their unique public `event_index`.
`engine_step_index` is deliberately omitted because it is internal process
metadata. Each event otherwise retains this exact order:

```text
event_index:u64be
kind:u8
player:optional u8
entity:optional locator string
public_passcode:optional u32be
from_zone:optional u8
to_zone:optional u8
count:optional u32be
amount:optional signed i32
counter_type:optional u32be
phase:optional u32be
winner:optional u8
win_reason:optional u8
effect_description:optional u64be
targets:u32 count, followed by lexicographically sorted locator strings
```

`match_context` fields are ordered:

```text
perspective_player:u8
duel_flags:u64be
knowledge.own_decklist_known:bool
knowledge.opponent_decklist_known:bool
own_deck
opponent_deck
```

Each static deck is encoded as `known:bool`, followed by sorted main-deck
passcodes and sorted extra-deck passcodes. An unknown deck must have empty
passcode vectors; otherwise projection fails closed.

The enum codes are fixed by this contract:

| Enum | Codes in declaration order |
| --- | --- |
| `SemanticZone` | `Unknown=0`, `MainDeck=1`, `Hand=2`, `MonsterZone=3`, `SpellTrapZone=4`, `Graveyard=5`, `Banished=6`, `ExtraDeck=7`, `FieldZone=8`, `PendulumRelevant=9`, `Overlay=10` |
| `Position` | `Unknown=0`, `FaceUpAttack=1`, `FaceDownAttack=2`, `FaceUpDefense=4`, `FaceDownDefense=8` |
| `LinkMarker` | `BottomLeft=0`, `Bottom=1`, `BottomRight=2`, `Left=3`, `Right=4`, `TopLeft=5`, `Top=6`, `TopRight=7` |
| `RelationshipKind` | `XyzMaterial=0`, `Equip=1`, `Target=2` |
| `VisibleEventKind` | `Unknown=0`, `TurnStarted=1`, `PhaseChanged=2`, `CardMoved=3`, `CardRevealed=4`, `Summoned=5`, `Set=6`, `Draw=7`, `Shuffle=8`, `RandomizationBoundary=9`, `LifePointsChanged=10`, `ChainActivated=11`, `ChainResolved=12`, `ChainEnded=13`, `CardDestroyed=14`, `CardBanished=15`, `CardReturned=16`, `PositionChanged=17`, `CounterChanged=18`, `Equipped=19`, `Unequipped=20`, `Targeted=21`, `Win=22` |

Unknown enum values, invalid player values, duplicate entity locators, and
duplicate event indices are rejected rather than assigned incidental bytes.
The serializer does not use unordered-container iteration.

Player-valued fields use `0` and `1`. The `winner` field is the terminal
`MSG_WIN` value and additionally permits `2` (`PLAYER_NONE`) for a legitimate
draw; values greater than `2` remain invalid.

## 4. Attached decision-context rule

`attach_decision_context(PlayerObservation&, DecisionRequest&)` may continue to
populate the internal v1 record. The public projector copies only `kind`,
`player`, and safe referenced locators. It drops the attached v1
`decision_id`, `continuation_id`, engine message metadata, engine-step
metadata, and v1 observation hash. It never hashes or embeds the full internal
`PlayerObservation` serialization.

Two internal observations may therefore have different v1 canonical bytes and
different v1 hashes because their private request identities differ while
their `PublicEnvironmentObservation` values and public digests remain equal.

## 5. Paired-world acceptance

The required fixture attaches distinct internal decision and continuation IDs
to two `PlayerObservation` values before projection. Both values then pass
through `canonical_public_safe_state_bytes` and
`project_public_observation`; no synthetic state string is supplied. It proves:

```text
World A hidden identity != World B hidden identity
PlayerObservation v1 bytes may differ
Public safe-state bytes equal
PublicEnvironmentObservation bytes equal
public_observation_digest equal
public_semantic_decision_id equal when public candidate domain is equal
```

Changing a visible `PlayerObservation` field, such as a life-point value,
must change the safe-state bytes, public observation digest, and public
semantic decision identity.

## 6. Compatibility and non-goals

`ygo.player_observation.v1` field semantics and canonical serialization remain
unchanged for the owning observation and internal integration consumers. Its
attached `DecisionContext` is not a policy-facing episodic wire object; the
separate public observation projection is the normative policy boundary.

This contract does not change observation visibility, Decision Protocol
legality, `EngineTrace v2`, rules, decks, or the production
`EpisodicEnvironment` implementation.
